## Conventions & gotchas for editing card assets by hand
- Cards are Unity YAML with `[SerializeReference]` graphs under `references.RefIds`; each node = `- rid: N / type: {class: X, ns: Y, asm: Assembly-CSharp} / data:`. `rid: -2` is the null sentinel (include the empty `- rid: -2` entry if you reference it). Value-logic classes (`IntegerValue`, `NumberOfTargets`, `EventAmountValue`, `MinionTotal*`) live in ns `GameSystems.Cards`; everything else has empty ns.
- **Rids are signed int64 — never exceed 9223372036854775807.** The `rid: -2` null sentinel proves Unity parses them signed; larger values risk clamping/wrapping at import. The original hand-added prefixes (9300…–9770…) overflowed this and were all renumbered 2026-07-14 to 9030…–9077… (same digit count, prefix map 93xx→90-3x, 9Nx0→90-Nx). Current hand-added prefix registry (one per file, uniqueness only matters within a file; digit count varies — Group ≤4 files use 19-digit rids, Group 5 files 16-digit, both fine): 9030 Escape Rune, 9040 Rat King, 9050 Rat, 9070 BlockAttackDamage, 9071 Thorn Crown, 9072 Sickle, 9073 Goblin, 9074 Shield, 9075 Final Resort, 9076 Plantkeeper, 9077 Shadow, 9078 Trickster, 9079 Fog of War, 9080 Hidden Grenade, 9081 Gambling spirit, 9082 Coat of Resonance, 9083 Heal Player, 9084 Plague Doctor, 9085 Curse, 9086 Rage, 9087 Aztec Priest, 9088 Cepter of Osiris, 9089 Taunting Amulette, 9090 Mirror, 9091 Beaked Mask, 9093 Cursed (status), 9094 Enraged (status). 9092 skipped; Taunt.asset has no refs. Next free: 9095.
- Effect1/Effect2 slots are rune-gated: bindings are INACTIVE until an item supplies matching runes, so `OnGameEvent(OnPlayed)` in those slots NEVER fires — use `OnEffectFieldIsActivated`/`DeActivated` pairs there.
- "While X" buffs = `RegisterAuraEffect`/`UnregisterAuraEffect` (self-cleaning, position-tracking), never one-shot modifiers.
- Enum indices: GameEventType 0=OnPlayed 1=RoundStart 2=RoundEnd 4=OnAttack 5=OnAboutToTakeDamage 6=OnDamaged 8=OnHealed 9=OnKilled 10=OnCombatResolution 13/14=Effect field (de)activated 15/16=StatusEffect applied/removed **17=OnPortalDamaged**; StatusEffectType 0=Plague 3=ItemPassive 5=Stun 6=Sleep 7=Stealth **8=Taunt 9=Cursed 10=Enraged** (masks are 1<<index); Resonance 0=Darkness 1=Plague 2=Death 3=Psychic 4=Life 5=Holy; DamageSourceType 0=Attack 1=Effect 2=Spell 3=StatusEffect. **Both GameEventType and StatusEffectType are append-only** — indices are serialized in assets. `parse_cards.py`'s name tables were updated to match.
- Status assets live in `Assets/Resources/StatusEffects/` (guids: Cursed `9f28f81987074fe19a0a61a812176ac9`, Enraged `2447d13abeea4c55abdefbb55ac9178c`, Taunt `697121959c984d929b6368f90ee7d0a5`). A status asset can carry `modifierHealth`/`modifierAttack` (single `[SerializeReference]` fields — YAML `modifierAttack:\n    rid: N`); older assets simply omit the fields.
- **Status trigger lists must never contain a null entry** (`triggers:\n  - rid: -2` = a one-element list holding null). Evasion/Sleep/Stun (and initially Taunt/Enraged) shipped exactly that, and `StatusEffectInstance.HandleEvent` had no null guard — the first event delivered to a minion holding one of those statuses null-ref'd inside the event drain (latent since Group 3; found in the 2026-07-14 wiring re-audit). Fixed both ways: the engine now skips null triggers (ctor + HandleEvent guard) and all five assets were cleaned to `triggers: []`. Use `triggers: []` for marker statuses.
- "Round" events fire every TURN (both players), and status durations tick per turn-end.
